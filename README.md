# RAG Knowledge Assistant

Question answering over 138 arXiv papers on LLMs and retrieval-augmented generation. Every answer cites its
sources, and the system refuses when the papers don't contain the answer. It runs fully locally (Qwen3-4B via
Ollama), and every design choice is backed by an ablation.

```
question ─┬─ dense (bge-base + FAISS) ─┐
          └─ BM25 ─────────────────────┴─ RRF fusion ─ cross-encoder rerank ─┬─ low score → refuse
                                                                             └─ Qwen3-4B → cited answer
```

## Results

Measured on the first benchmark: 200 answerable and 50 unanswerable questions, with Qwen3-4B as the judge. A rerun
with a 70B+ judge and multi-hop questions is in progress.

| retrieval | Recall@1 | Recall@5 | MRR@10 |
|---|---|---|---|
| fixed-size chunks + dense (baseline) | 0.325 | 0.605 | 0.439 |
| structured chunks + dense | 0.395 | 0.680 | 0.517 |
| structured + BM25 | 0.575 | 0.825 | 0.683 |
| structured + hybrid (RRF) | 0.450 | 0.810 | 0.598 |
| **structured + hybrid + rerank** | **0.645** | **0.880** | **0.747** |
| fine-tuned embedder + dense | 0.455 | 0.765 | 0.589 |

| end to end | baseline | full system |
|---|---|---|
| answer accuracy | 0.640 | **0.840** |
| faithfulness (claims supported by sources) | 0.891 | **0.973** |
| valid citations | 0.906 | **0.960** |
| correct refusal on unanswerable | 0.920 | **0.960** |
| false refusal on answerable | 0.173 | **0.013** |

- **Reranking is the biggest single win:** +20 points Recall@1 over hybrid retrieval alone.
- **Structure-aware chunking helps on its own:** +7.5 points Recall@5 with the same retriever.
- **BM25 beats dense retrieval here,** because papers are full of exact names ("RefoMed", "BIOMISTRAL"). Hybrid
  retrieval is still the better input to the reranker.
- **Fine-tuning the embedder** on 704 synthetic pairs with mined hard negatives raises dense Recall@5 from 0.68 to
  0.77. Once the reranker is added, both embedders reach the same recall.
- **Better retrieval shows up as fewer false refusals:** when the right passage is in context, the model stops
  saying "I don't know".
- **Reranking only the top 20 candidates** gives the same recall as 30 at two-thirds of the latency.

## How it works

- **Chunking.** PDFs are converted to markdown, split on section headings, and the reference list is dropped.
  Chunks are cut on the embedder's own tokens (320 + 64 overlap), so none are silently truncated. Each chunk is
  prefixed with `paper title | section`.
- **Retrieval.** Dense and BM25 results are merged with reciprocal rank fusion, then a cross-encoder
  (bge-reranker-base) rescores the top 20.
- **Abstention.** If the best reranker score is below a threshold, the system refuses without calling the LLM.
- **Generation.** Answers stream over SSE with inline `[n]` citations. There's no framework: retrieval and
  generation are about 100 lines of plain Python.

## Evaluation

- **Benchmark.** Generated by a stronger judge model, not the 4B system under test. It has three kinds of
  questions:
  - **single-hop:** answered by one passage;
  - **multi-hop:** need two sections of a paper;
  - **unanswerable:** written from 12 papers that are downloaded but never indexed, so they look exactly like real
    questions.
- **Splits.** A third of the questions form a dev split, used only to tune the abstention threshold. Everything
  reported is on the rest.
- **Relevance.** A retrieved chunk counts as a hit if it is from the gold paper and covers at least half of the
  gold passage. This keeps metrics comparable across chunking schemes. A multi-hop question counts as found only
  when all of its passages are retrieved.
- **Judging.** The judge model grades correctness against the reference answer and checks that every claim is
  supported by the retrieved sources.
- **No leakage.** Embedder fine-tuning never trains on test passages or their neighbours.

## Run

```bash
pip install -e ".[dev]" && ollama pull qwen3:4b-instruct
```

```bash
python -m rag.ingest download && python -m rag.ingest index && uvicorn rag.api:app --port 8000
```

Then open http://localhost:8000, or run everything with `docker compose up --build`.

To reproduce the evaluation, point `RAG_JUDGE_URL` and `RAG_JUDGE_MODEL` at any OpenAI-compatible server (e.g.
vLLM), then run:

```bash
python -m rag.ingest index --fixed --out data/index_fixed && python -m experiments.testset && python -m experiments.finetune
```

```bash
RAG_EMBED_MODEL=models/bge-base-rag python -m rag.ingest index --out data/index_ft && python -m experiments.evaluate
```
